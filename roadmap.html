Curriculum roadmap · draft v0.2

Infinite Teammates

Build a Grokbot from scratch, starting with a single API call. Every level adds one thing, and every level exists because the one before it broke.

20 levels Season One ≈ 60 hrs Railway moment at hour 35

The ladder

Read the right-hand column first. Each level exists because you ran a task on the previous level's code and watched it fail. That's what sets the order — not difficulty, and not what's conventional to teach next.

Part I

The Loop

Get from an API call to a working agent. The loop you write in Level 3 is the core of everything else — the later levels mostly give it more things it can do.

00

Call a model

ask.py "why is the sky blue" → an answer. One file, one dependency. No framework, no database, no web server.
Learn
Where the API key lives, system vs. user messages, tokens as the unit of both cost and memory
Done when
You print the answer along with the token count and cost of the call
Effort
30 min

SidebarPrint the raw JSON response once and look at it. You won't need to again, but it's worth seeing what you're actually working with.

01

Hold a conversation

Breaks

"My name is Patrick." → "Hi Patrick." → "What's my name?" → it has no idea.

A REPL that writes down what happens as it happens: one line appended to history.jsonl for every message you send and every one that comes back. When it's time to call the model, read that file and build the list of messages from it.
Learn
The model is stateless, so keeping the record is your job. Message roles. Building the request out of the record, rather than letting the request be the record.
Done when
You quit mid-conversation, restart, and it picks up where you left off. Then delete the last two lines of the file and watch the conversation rewind.
Effort
1 hr

Why the extra stepHolding a list in memory is simpler and works fine today. Writing it down first pays off at Levels 5, 10 and 12, where you'll want to send the model something different from what actually happened and still have the real record to fall back on.

02

Give it one tool

Breaks

"What time is it in Tokyo?" → a confident, wrong answer. "What's 47281 × 9912?" → also confident, also wrong.

One tool — get_current_time(tz) — described as a JSON Schema, plus the code to notice the model asked for it, run it, and send the result back.
Learn
Tool schemas, the request → execute → result round trip, and why the tool's description matters more than its name
Done when
The model asks for the tool, your code runs it, and the answer is right because of that
Effort
2 hrs

The whole pointThe model doesn't call your function. It sends back a message saying it wants to, and your code decides whether to run it. Every tool in every later level works this way.

03

Build the agent loop

Breaks

"What's today's date, and how many days until Christmas?" → your handler runs one tool and stops.

Wrap the whole thing in a while: call the model, run whatever tools it asks for, feed the results back, repeat until it stops asking. Add a tool registry so a new tool is one entry rather than one branch.
Learn
The agent loop, dispatching tools by name, when to stop, and why the record grows so fast. One pass through the loop is one model call plus whatever tools it asks for — a single request from you can take several passes.
Done when
It chains three or more tool calls on its own to finish one thing you asked for once
Effort
3 hrs

MilestoneThis is an agent. It's about forty lines. Cursor, Claude Code, and everything else in this category are wrapped around a loop that looks like this.

04

Harden the loop

Breaks

It asks for a tool that doesn't exist. It passes "3" where you wanted an int. It calls the same tool forty times. Your tool raises, and the process dies mid-task.

Validate arguments before dispatching. Catch tool exceptions and send them back to the model as results so it can correct itself. Cap iterations, time out slow tools, retry API errors with backoff.
Learn
Letting the model see and recover from its own errors, iteration limits, idempotency, knowing when to stop trying
Done when
You deliberately sabotage a tool and it either recovers or gives up with a clear explanation, without a traceback
Effort
3 hrs

NoteBoring level, and most tutorials skip it. It's a lot of why tutorial agents fall over the moment you give them a real task.

05

Stream it

Breaks

You give it a task twenty tool calls deep and stare at a blank terminal for ninety seconds, unsure whether it's working, stuck, or looping through your money.

Streaming responses, and a live view built by watching the file from Level 1 as it's written. To make that possible you add the lines that don't exist yet: the tool being called, the result coming back, and later the one that says it's stuck and needs you.
Learn
Streaming, showing work in progress without inventing a second copy of the truth, and deciding what has to be written down for a reader to reconstruct the screen
Done when
You can watch it work, see each tool call land, interrupt it — and replay the whole session afterward from the file alone
Effort
3 hrs

Why hereThe lines you add now are what the takeover screen reads at Level 9. Easier to settle while the system is still small enough to change.

Part II

The Computer

Give the loop somewhere to put files and a way to run them. Still all on your laptop, with your real files, which is worth keeping in mind.

06

Give it files

Breaks

"Refactor this 400-line file." You paste the file in. It pastes 400 lines back. You paste those into your editor. This isn't software.

An agent_workspace/ and four tools: list_files, read_file, write_file, edit_file. Every path resolved and confined to the workspace root. All four call one small module that does the actual reading and writing, instead of touching the filesystem themselves.
Learn
Path traversal and why ../ is your first security bug, why targeted edits work better than rewriting whole files, how file size eats your context budget
Done when
It writes a working Python file whose contents you never saw in the chat
Effort
3 hrs

Why the extra moduleIt looks like pointless indirection today, since it's four functions wrapping four other functions. At Level 15 you point it at a container instead of your laptop and none of the tools change.

07

Shell access, and the first permission gate

Breaks

It writes primes.py and can't run it. So you add run_command. Ten minutes later it runs something you didn't expect and your stomach drops.

run_command, going through its own small module the way the file tools do, plus an approval gate: auto-allow a read-only list, ask you about everything else, refuse a few things outright, and record every command with its result.
Learn
The difference between what the agent can do and what it's allowed to do, why allowlists work and denylists don't, pausing for a human without treating it as an error, audit logs
Done when
It writes → runs → reads the traceback → fixes → runs → succeeds, and you approved exactly the commands you meant to
Effort
4 hrs

ForeshadowingThe pause-and-wait-for-a-human mechanism you build here is the same one Level 9 uses. There it waits for a login instead of an approval.

Part III

The Handoff

A browser the agent can drive, and a clean way to hand you the keyboard when it hits something only you can do. These two levels are why you started.

08

Give it a browser

Breaks

"Check my Railway account." There's no API plugin for Railway and there never will be — same as your bank, your landlord's portal, and most of the software your life runs on.

Playwright as a set of tools: navigate, click, type, read_page, screenshot, scroll. Decide deliberately how a page gets represented to the model, and keep the browser context alive between tasks.
Learn
Accessibility tree vs. screenshot-and-coordinates, element references that survive a re-render, waiting and flakiness, cookies and session persistence. Expect this to be the flakiest thing you own.
Done when
It finishes a multi-page task on a site with no API, from a cold start, twice in a row
Effort
8 hrs
09

Human takeover The Railway moment

Breaks

It opens Railway and hits a login wall. It can't continue, and the one thing that would let it continue is the one thing it must never be handed.

Four pieces. One: it notices it's stuck on something only you can do and says so instead of guessing. Two: you can see its browser and type into it. Three: control passes both ways cleanly, with the agent parked while it waits. Four: the logged-in session survives the handoff and it picks the task back up.
Learn
Treating "needs a human" as a normal state rather than a failure, streaming a live browser view and forwarding input back into it, who owns the session, and why having you log in on the agent's machine beats any scheme where you hand over a password
Done when
You say "check my Railway account," log in when it asks, and it finds your instance and helps you downgrade the plan — on your own software, without a password ever entering a chat box
Effort
8 hrs

Where you areRoughly 35 hours in, a little over half of Season One. Everything after this makes it reliable and connects it to your actual life.

Part IV

Reliability

The browser levels leave you with something that works and something that works sometimes. Both problems come from the same place, and both need measuring before they can be fixed.

10

Compaction

Breaks

Six pages into a browsing task the request fails outright. Each read_page dumped thousands of tokens into the transcript and the context window is full.

Put a function between "about to call the model" and the call itself. It reads the record and returns the messages to send, which is where you count tokens and summarize the old ones. Decide explicitly what it may never drop: the system prompt, the current objective, the last few exchanges, anything you pinned.
Learn
Context windows as a hard limit you will hit, summarizing history without losing the thread, how summarizing breaks prompt caching, what a long session actually costs
Done when
A two-hour browsing session finishes without erroring and it still knows what you asked for
Effort
4 hrs

Keep that functionEverything that needs to change what the model sees goes here eventually: trimming history now, injecting a reminder at Level 12, checking permissions in Season Two. It's the only place that decides what actually gets sent.

11

Evals

Breaks

The Railway task works about six times in ten. You rewrite the prompt and it feels better. You genuinely cannot tell whether it is.

Twenty to thirty fixed tasks with checkable outcomes, a runner that executes them against a snapshot, and a report: pass rate, mean cost, mean steps, and a diff against the last run.
Learn
Building an eval set, when a deterministic check is enough and when you need a model to judge, catching regressions from prompt changes, tracking cost and step count alongside correctness
Done when
You can say "that change took pass rate from 61% to 84% and cost up 12%" and defend the number
Effort
5 hrs

NoteEverything before this was tuned by feel. Everything after can be measured, which matters most for the parts that are already flaky.

Part V

Making it yours

It works and you can measure it. Now give it a memory of you, access to your actual accounts, and a way to add the next account cheaply.

12

Durable memory

Breaks

"Why did we pick Postgres again?" Compaction summarized that away last Tuesday, and the summary said "discussed database options."

You already have what was said — that's the file from Level 1, one per session. What's missing is a place for the things worth keeping across sessions: memory.md, plus remember, search_memory, and read_session(date) so it can go back and look.
Learn
Why what was said, what it's doing now, and what it knows about you want to be three separate things. Retrieval as an ordinary tool call. Deciding when something is worth writing down, which turns out to be the hard part.
Done when
In a brand-new session, "what did we decide about the database last week?" gets the right answer, and you can open a file and see why
Effort
5 hrs

Graduation pathMarkdown, then SQLite, then embeddings — each when the previous one visibly stops working. Start with a file you can open, because you'll be debugging what it thinks it remembers.

13

Gmail, and your first real OAuth

Breaks

"Find the email with my flight details for tomorrow." You could point the Level 8 browser at Gmail, and it's slow, brittle, and breaks whenever the page changes. Some things deserve an API.

The full authorization code flow: consent screen, scopes, token storage, refresh. Tools search_email and read_email. And a new state to handle — the tool exists but isn't connected yet, so it emits auth_required and your UI offers "Connect Gmail."
Learn
OAuth2 authorization code flow, scopes and asking for the minimum, refresh tokens, where to keep secrets, handling a tool that exists but isn't authorized
Done when
It finds a real email in your real inbox, and still works tomorrow after the access token has expired
Effort
6–8 hrs

Budget warningConfiguring Google's consent screen will take an afternoon by itself. Plan for it.

14

The plugin system

Breaks

You start on Google Calendar and find yourself copying the entire Gmail auth module and changing four strings.

A convention — plugins/<name>/{manifest, auth, tools} — with a registry that finds them, per-plugin credential storage, and tool schemas assembled at startup. Calendar is the proof: an hour, not a day.
Learn
Tool registries, manifests, discovering what a plugin can do, assembling schemas at runtime. Read the MCP spec at the end of this level and you'll recognize what you just built.
Done when
A third plugin — GitHub, Linear, whatever you actually use — takes under an hour end to end
Effort
5 hrs
Season Two

The Fleet

Sketched only. These get designed properly once Season One is done and you know what you actually built. This half costs real money to run and is mostly infrastructure work.

15

Sandbox it

Breaks

You notice that for fifteen levels this thing has had shell access to your actual laptop, your actual SSH keys, and your actual browser profile.

The agent, its browser, and its workspace move into a container with filesystem and network isolation, resource limits, and a clean rebuild. Because the file and shell tools each go through one module already, most of this is pointing those two somewhere else.
Effort
8 hrs
16

A cloud computer per agent

Breaks

Containers die and take the logged-in Railway session with them, and everything still needs your laptop to be awake.

An orchestrator with a real lifecycle — create, start, stop, snapshot, resume, destroy — over VMs with persistent disks. Base images, boot time, and the cost of leaving one running.
Effort
2 weekends + a bill
17

Persistent agent identity

Breaks

One agent with one memory file that knows about your travel plans, your codebase, and your finances at once, and brings up the wrong one every time.

Named teammates, each with its own instructions, memory, connected plugins, workspace, computer, and task history — and many conversations under one identity rather than one identity per chat.
Effort
6 hrs
18

Background execution

Breaks

You give it a twenty-minute job, close your laptop, and it dies with the HTTP request that started it.

Work moves onto a queue with real workers: checkpoints, resumption, heartbeats, retries, and a notification when the thing you asked for at 9am is done at 11.
Effort
10 hrs
19

Production

Breaks

Someone other than you wants to use it.

Secret storage, per-agent audit trails, approval policy, rate limits, spend caps, reaping idle VMs, tracing, and enough observability to answer "what did it do at 3am and what did it cost."
Effort
Unbounded — this is the job, not a level

What's not in the course

Things you'd expect to see in something like this, and why they aren't here.

  • Training or fine-tuning a modelOut of scope It would roughly double the length, and it isn't the part you're missing. You're building the software around the model.
  • Agent frameworksDeferred to L14 You write your own registry, loop, and record-keeping first. Then read the MCP spec, and read how DeepSeek Harness lays out its agent loop and tool pipeline. Both take an hour instead of a week once you've built the thing they're generalizing, and you'll have opinions about the parts you'd have done differently.
  • Agents talking to agentsAppendix Hard to motivate for a personal assistant. Most of what's useful at this scale is running a subagent to keep the main context clean, which is a paragraph in Level 14 rather than a level of its own.
  • Vector databases and RAGPart of L12 Reached for when a markdown file stops being enough. Nothing else on the ladder depends on it.

Still open

Assumed so the roadmap could exist. Cheap to change now, expensive later.

Repo shape: one folder per level, prose beside the code

levels/03-loop/ runs on its own, and levels/03-loop/LESSON.md explains what changed since Level 2 and why. You can start at any level, and diffing two folders shows exactly what a feature cost. The duplication grows; from Level 12 on the folders share a core/ package.

AlternativeOne codebase that grows. More satisfying to watch, much harder to join partway through.

Stack: Python through Level 7, TypeScript from Level 8

The loop and tool schemas read cleanest in Python, which matters most where the concept is the lesson. The browser and the takeover UI are more natural in TypeScript.

AlternativeAll TypeScript. One language throughout, noisier early lessons.

Provider: one model API, no abstraction layer

An adapter at Level 0 would hide the exact thing Level 0 exists to show. Pick one, use it plainly, add a shim later only if a lesson needs it.

Needs youWhich one, and whether you already have a key.

Audience

Changes the tone, the level of hand-holding, and how much of the code is written for the reader versus left as the exercise.

Needs youYou learning in public, or a finished thing strangers follow.

Where it ends

Season One is coherent on its own and finishes on the Railway moment. Season Two is sketched far enough that the architecture doesn't paint itself into a corner.

OpenWhether a container per teammate is a fine ending, or whether VM-per-chat fidelity to Cursor actually matters to you.
