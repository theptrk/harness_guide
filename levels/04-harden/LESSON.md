# Level 4 — Harden the loop

## What broke

Level 3 lets exceptions from a tool escape the agent loop. Give its clock an invalid timezone:

```text
you › Use get_current_time with the timezone Mars/Olympus.

tool › get_current_time({"timezone":"Mars/Olympus"})
call failed: 'No time zone found with key Mars/Olympus'
```

The model requested a function call, but the file contains no matching `function_call_output`. The turn cannot continue.

Level 4 handles two classes of failure differently:

- A tool failure becomes a `function_call_output`. The model can read it and decide what to do.
- An API or harness failure stops the turn. Another model call cannot repair a failed network request, an incomplete response, or broken persistence code.

---

## Run it

```sh
uv run --env-file .env levels/04-harden/main.py --new
```

Use the same invalid timezone:

```text
you › Use get_current_time with the timezone Mars/Olympus. If it fails, explain the failure.

tool › get_current_time({"timezone":"Mars/Olympus"})
tool ‹ {"error": {"type": "ZoneInfoNotFoundError", "message": "'No time zone found with key Mars/Olympus'"}}

››› The request failed because `Mars/Olympus` is not a recognized IANA time zone. No current time could be retrieved.
```

The tool still failed. The loop did not fail.

## Tool failures are tool output

`run_tool()` contains the operations that can fail because of a model-selected tool call:

```python
def run_tool(tool_call) -> str:
    try:
        arguments = json.loads(tool_call.arguments)
        tool_function = TOOL_FUNCTIONS.get(tool_call.name)
        if tool_function is None:
            raise LookupError(f"unknown tool: {tool_call.name}")
        return tool_function(**arguments)
    except Exception as error:
        return tool_error(type(error).__name__, str(error))
```

This catches malformed JSON, a name missing from the registry, arguments that do not match the Python function, and exceptions raised by the function. It does not catch failures from the API call, history file, or rest of the loop.

The error is returned with the original `call_id`:

```python
history.append_item(
    chat_file_path,
    {
        "type": "function_call_output",
        "call_id": tool_call.call_id,
        "output": tool_result,
    },
)
```

The model sees a completed tool request whose output contains an error. It can correct an argument, choose another tool, or explain the failure.

`strict: True` constrains the JSON shape generated by the model. It cannot prove that a string names a real timezone. The Python function still validates that when it constructs `ZoneInfo(timezone)`.

## Bound the loop

Level 3 will execute tool calls until the model stops requesting them. Level 4 allows five:

```python
TOOL_CALL_LIMIT = 5
```

The previous level's exercise needs three tool calls. Five leaves room for two corrected calls while placing a concrete bound on tool execution. This is a budget for this tutorial, not a universal value.

When the model requests a sixth call, the harness returns a `ToolCallLimit` error without executing it. The next model call sets:

```python
tool_choice="none"
```

The model must answer using the results it already has. The limit therefore bounds executed tools rather than abandoning a `function_call` without its required output.

Try asking for the current time in six timezones. The sixth request should receive a `ToolCallLimit` result, followed by an answer.

## Check the response before executing it

An HTTP request can succeed while the model response has:

```json
{
  "status": "incomplete",
  "incomplete_details": {
    "reason": "max_output_tokens"
  }
}
```

The other incomplete reason is `content_filter`.

Level 4 saves every output item, then calls `require_complete(response)` before looking for a tool call. Incomplete output is marked:

```json
{"include_in_input": false}
```

`history.get_input_items()` excludes it from later API input. This preserves the record without replaying a partial message or function call.

You can force the model to run out of output tokens:

```sh
printf '%s\n' 'What time is it in Tokyo?' |
  MAX_OUTPUT_TOKENS=16 uv run --env-file .env levels/04-harden/main.py --new
```

One run produced an incomplete function call whose arguments ended at:

```json
{"arguments":"{\"timezone\":\"","status":"incomplete"}
```

The program stopped with:

```text
harness failed: model response incomplete: max_output_tokens; no tool from this response was executed
```

Executing that tool would require guessing the missing argument. Sending the identical model request again would use the same token cap. This level stops instead. A later design could raise the cap or continue partial answer text, but it must not execute a partial tool call.

Retrying after `content_filter` is also not useful without changing the request.

## API retries and timeouts

The client is configured explicitly:

```python
client = OpenAI(max_retries=2, timeout=30.0)
```

The SDK retries connection failures, request timeouts, rate limits, and selected server errors. Two retries means at most three attempts. If those attempts fail, the API exception stops the program with a short error instead of entering another agent pass.

The 30-second API timeout does not stop a Python tool. `get_current_time()` performs no blocking network or subprocess work, so it needs no separate timeout. A later HTTP or shell tool must set a timeout on that operation. A thread timeout only stops waiting for a function; it does not stop the function itself.

## Done when

1. Pass `Mars/Olympus`. The model receives the tool error and explains it without a stack trace.
2. Ask for six timezones. No more than five tool functions execute, and the model gets a final call with tools disabled.
3. Set `MAX_OUTPUT_TOKENS=16`. The program reports an incomplete response and does not execute the partial function call.
